# H2 B0 exact Nix runtime-closure POC

This nested flake is a bounded authoring candidate for
`BMF_BUILD_RUNTIME_REPRODUCIBILITY_AND_DEPENDENCY_CLOSURE_PROOF`. It does not
contain platform provider code, a platform graph/lowering contract, blur
execution, semantic conformance, GPU work, or any B1 work. The smoke harness
includes one deliberately minimal BMF CPU graph, but this document does not
claim that the required identity-sensitive reruns have passed. No build, image,
distribution, or conformance result is claimed by this document.

The frozen identities are `ProviderId=bmf` and the future stable
`ProviderImplementationId=bmf.cpu.v1`. This POC deliberately creates no
`ProviderRuntimeBundleId`. Provider implementation identity, runtime packaging,
and a future runtime dependency fingerprint are separate concerns:
`ProviderImplementationId != ProviderRuntimeBundleId != RuntimeDependencyFingerprint`.

## Outputs and build shape

The x86_64-linux outputs are:

- `ffmpeg448`: shared FFmpeg libraries plus `ffmpeg` and `ffprobe`. Autodetected
  external libraries, network support, GPL, and nonfree features are disabled.
  The build does not add external codec libraries. Its development output is
  used only while compiling BMF and is excluded from `runtimeClosure`. Exact
  configure flags are installed as `share/bmf-b0/ffmpeg-configure.json`.
- `bmfCpu`: a direct CMake assembly of BMF's Python/native runtime. This avoids
  `setup.py` dependency resolution while retaining the assembled `bmf/lib`,
  builtin config, C++ modules, Python modules, and Python SDK. Headers are not
  copied into the runtime package. Build identity and inputs are installed as
  `share/bmf-b0/bmf-build.json`.
- `runtimeClosure`: BMF, the nixpkgs Python/numpy runtime, FFmpeg, and the
  `bmf-b0-smoke` entrypoint. Its wrapper replaces `PATH` and `PYTHONPATH` with
  exact store-bound values and never sets `LD_LIBRARY_PATH`.
- `pureNixImage`: the low-cost Nix-generated minimal OCI feasibility target,
  with the same `bmf-b0-smoke` command.
- `debianBookwormSlimClosureImage`: a compatibility-base seam that places the
  same Nix closure over Debian bookworm-slim. Debian is a runtime compatibility
  mechanism only; apt is not used and is not dependency authority.

The dependency-local enabled/disabled module inventory is:

|---|---|---|---|
| dlpack demo/mock executable (`mock`) | `BUILD_MOCK=OFF` | Disabled | It captures dlpack's immutable-source `bin` output directory when created and is not in the BMF runtime dependency closure. |

No BMF or FFmpeg feature flag is changed by this dependency-local setting.

Native files are first checked by Nix's automatic ELF dependency patcher and
then assigned an exact RPATH consisting only of the installed BMF library
directory and locked Nix FFmpeg/Python/elfutils/compiler-runtime library
directories. No ambient `/usr`, PATH FFmpeg, or host shared-library path is a
declared dependency source. `elfutils` is used for backward-cpp stack support;
its exact package identity is inherited from the locked nixpkgs revision and
must be observed in closure evidence.

The POC-local closure patch removes unconditional `/usr/java` build includes
and the upstream runtime's default `/usr/local`, `/opt`, and current-directory
module repositories. It preserves the `bmf_sdk::s_bmf_repo_root` and
`bmf_sdk::s_bmf_mods_path` ABI symbols, defining both as the intentionally
non-store-object and Nix-runtime-unwritable path
`/nix/store/.bmf-disabled-module-install`. This keeps the unrelated
`module_manager install` default fail-closed without adding either symbol back
to `ModuleManager::init()` search roots. Ambient module search remains absent;
BMF's store-relative builtin configuration and assembled `cpp_modules`,
`python_modules`, and `go_modules` searches remain. The separate dlpack setting
disables its out-of-closure mock executable, and the retained containment patch
restores BMF's runtime output directory after FetchContent processing. These
are build/closure compatibility measures, not platform provider or semantic
changes. The same ABI, installation-default, and module-search facts are
recorded in `share/bmf-b0/bmf-build.json` under
`module_manager_path_compatibility`.

## Two bounded smoke layers

The harness reports two explicitly separate layers:

- `IMPORT_AND_NATIVE_LINKAGE_SMOKE` preserves the existing BMF/numpy imports,
  native `_bmf` and `_hmp` resolution, compiled BMF commit/version checks, exact
  FFmpeg/ffprobe prefix checks, `PYTHONNOUSERSITE=1`, and Nix-store-only absolute
  `sys.path` checks.
- `MINIMAL_BMF_GRAPH_EXECUTION_SMOKE` creates an exact 2x2 P6 PPM fixture in
  memory from the byte sequence for red, green, blue, and white pixels. It
  writes that deterministic input only to a fresh temporary working directory,
  records its SHA-256, passes its absolute path to BMF, and executes a
  `c_ffmpeg_decoder` -> `c_ffmpeg_encoder` graph with the encoder configured as
  a null sink. The harness records and checks both node/module names.

After graph completion, the second layer reads `/proc/self/maps`, requires a
mapped `libbuiltin_modules` object, resolves every matching path, and requires
each one to be beneath the installed BMF package root derived from
`Path(bmf.__file__).resolve().parent`. The temporary current directory,
`/usr/local/share/bmf_mods`, `/opt/tiger/bmf_mods`, and host `/usr` or `/home`
Python site-package paths are excluded as module authorities. The original
working directory is restored before the temporary directory is cleaned up.

This freezes
`MINIMAL_GRAPH_EXECUTION_IS_RUNTIME_SMOKE_NOT_SEMANTIC_CONFORMANCE_V1`. Decoding
one deterministic frame into a null sink proves only minimal runtime graph
execution and built-in loading. It is not a semantic-conformance corpus and
does not prove Gaussian blur, output equivalence, cross-runtime conformance,
Provider implementation, platform lowering, GPU behavior, or B1 work.

## Hermes commands

Run these from this directory in the authorized Nix builder. Lock generation is
intentionally left to Hermes:

```sh
nix flake lock
nix flake metadata --json > flake-metadata.json
nix build .#ffmpeg448
nix build .#bmfCpu
nix build .#runtimeClosure
nix run .#smoke > runtime-smoke.json
nix path-info --json -r .#runtimeClosure > runtime-closure.json
nix-store --query --references "$(nix path-info .#bmfCpu)" | sort > bmf-direct-references.txt
nix build .#pureNixImage
```

The smoke emits one JSON object containing the distinct import/linkage and
minimal-graph statuses plus their observations. `PASS` is emitted only after
all import, identity, path-authority, graph-execution, and mapped-built-in
assertions complete. Until Hermes runs the commands above against the frozen
identities, this is a committed validation harness rather than a passing-result
claim. After those identity-sensitive reruns, their correction evidence must
supersede the old sealed smoke evidence.

For the compatibility-base seam, the accepted Debian manifest digest is fixed
to

## Decision boundaries

The governing principles are:

- `NIX_OWNS_PROVIDER_RUNTIME_BUILD_DEPENDENCY_CLOSURE_V1`
- `BASE_OS_IS_RUNTIME_COMPATIBILITY_MECHANISM_NOT_DEPENDENCY_AUTHORITY_V1`
- `PROVIDER_IMPLEMENTATION_ID_IS_INDEPENDENT_OF_RUNTIME_PACKAGING_V1`
- `NIX_GENERATED_MINIMAL_OCI_IS_THE_LONG_TERM_RUNTIME_PACKAGING_TARGET_V1`
- `BUILDABLE != DISTRIBUTABLE`
- `RUNTIME_ELIGIBILITY != SEMANTIC_CONFORMANCE`
- `CAN_RUN != OUTPUT_EQUIVALENCE`

In particular, **BUILDABLE != DISTRIBUTABLE**. Apache-2.0 for BMF and a bounded
LGPL-compatible FFmpeg configuration do not prove that the resulting closure
is distributable. Hermes must still inspect the lock, exact closure, dynamic
linkage, configure evidence, licenses, and OCI contents. Likewise, successful
import and execution would only be runtime smoke evidence; it would not prove
runtime eligibility, Gaussian-blur semantics, or output equivalence.

## Likely first-build correction points

The Debian normalized archive hash has been resolved and pinned. Other likely
first Nix feedback is compatibility between this older BMF/pybind11 tree and
the Python/compiler versions at the pinned nixpkgs commit; backward-cpp's
libdw discovery; CMake's exact FetchContent override spelling; and RPATH
coverage for native libraries under nested `Module_*` directories. Corrections
must remain inside this directory, keep all source identities and feature flags
fixed, and must not turn tests off beyond the already authorized package-build
setting or introduce an ambient dependency fallback.
