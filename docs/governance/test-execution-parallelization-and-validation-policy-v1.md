# Test execution parallelization and validation policy V1

`governance/TEST_EXECUTION_TOPOLOGY_LEDGER.tsv` is the tracked authority for every active Gradle `Test` task. The policy applies `maxParallelForks` per task, not as a global JUnit or high-fork switch. Its exact classification vocabulary is `PURE_PARALLEL_SAFE`, `SPRING_HEAVY_BOUNDED`, `SERIAL_ONLY`, and `REVIEW_REQUIRED`.

The authoritative census contains 51 exact active `Test` task paths, including the realized `:platform-algorithms:test` parent task alongside `:platform-algorithms:graph:test`. Its zero discovered tests are not parallel-safe evidence, so it remains `REVIEW_REQUIRED` with one fork. The zero-test addition does not change the raw full-suite universe (`8209`) or topology gross count (`8215`).

`PURE_PARALLEL_SAFE` is a promotion, not a review assertion. The exact original 21-task enrollment is now canonical with `CLASSIFICATION=PURE_PARALLEL_SAFE` and `CURRENT_MAX_PARALLEL_FORKS=2`; every enrollment row is `SEALED_PROMOTION` and binds both evidence columns to the tracked `governance/TEST_EXECUTION_PARALLELIZATION_PROMOTION_RECEIPT_V1.tsv`. The static validator accepts no arbitrary `evidence/...` prefix: it requires that exact receipt and verifies its complete contents, including the external report filenames and SHA-256 values. Missing, substituted, or changed receipt bytes fail closed. `SPRING_HEAVY_BOUNDED` is the positive Spring-context class and is capped at `maxParallelForks=1`; it is used for billing, notification, datasource, and Spring worker tasks unless a concrete exclusive resource requires `SERIAL_ONLY`. `REVIEW_REQUIRED` and `SERIAL_ONLY` are both capped at one; every serial-only task has a matching non-blank entry in `TEST_EXECUTION_SERIAL_ONLY_LEDGER.tsv`.

The root Gradle policy sets `junit.jupiter.execution.parallel.enabled=false` for every test task. It intentionally does not enable global JUnit intra-JVM parallelism, use a global 16/32/80 fork value, or make a module-wide assertion stronger than the task boundary permits. `platform-app` is capped at one fork. Gradle mechanically creates two phases: only `PURE_PARALLEL_SAFE` and `SPRING_HEAVY_BOUNDED` tasks can participate in the module-level parallel phase; all `REVIEW_REQUIRED` and `SERIAL_ONLY` tasks wait for that phase and are chained with `mustRunAfter`, so restricted tasks cannot overlap even under `--parallel`.

The default Gradle profile now has the exact scheduling topology proven by Hermes: the 21 sealed pure tasks use two JVM forks, Spring and restricted tasks remain one fork, and global JUnit intra-JVM parallelism remains disabled. `-PtestExecutionCandidateProfile=true` remains an opt-in only for future `CANDIDATE_ONLY` enrollment. It overlays only unsealed review-required rows, so it is a no-op for these sealed rows and cannot double-promote them.

Validation levels are ordered and fail closed:

| Level | Required action |
| --- | --- |
| `V0_PRE_COMMIT` | Static topology, fork, ledger, and forbidden-parallelism validation. |
| `V1_IMPLEMENTATION` | Focused executable policy tests and negative controls. |
| `V2_CANDIDATE_FCV` | `FULL_DETERMINISTIC_BACKEND_SUITE`, then XML accounting that proves execution, arithmetic, and identity/universe parity. |
| `V3_CHECKPOINT` | Selected serial replay and benchmark review. |

The old serial policy is authoritative until canonical publication review. A benchmark is evidence, never an automatic promotion mechanism: matrix mode runs workers `1,8,16,24,32` once each, then winner-replay mode runs only the selected winner at least three times. The runner requires a frozen wrapper command containing `-PtestExecutionCandidateProfile=true`, `--rerun-tasks`, and `test`, and appends exactly one `--parallel --max-workers=N` profile per run. It requires external report, per-run output, and raw expected-universe paths. Every run captures stdout/stderr and `/usr/bin/time -v` output under a unique external path, records the per-run RSS/CPU measurement confidence, and reports `RESOURCE_COLLISIONS=0` only for an exit-zero run whose captured log has no bind/address, file/database-lock, or Testcontainers/resource-conflict signature. It compares exact JUnit identities and skip count to the external raw baseline universe; an exit code alone never passes, and no failure is retried.

`TEST_EXECUTION_ACCOUNTING_BASELINE.tsv` distinguishes the `8094` top-level expected universe, `8209` raw recursive universe, and `29` expected skips from the `8215` topology gross selection count. `TEST_EXECUTION_DECLARED_OVERLAPS.tsv` accounts for the six intentional selections made by the three custom tasks; duplicate execution is therefore declared and reconciled rather than silently accepted.

Use `scripts/ci/test_execution_policy.py` for static validation, `scripts/ci/census_test_execution_topology.py --check` for the documented ledger census alias, `scripts/ci/run_full_deterministic_backend_suite.py` for the actual V2 coordinator, `scripts/ci/test_execution_accounting.py` for report accounting, and `scripts/ci/run_test_execution_benchmark.py` only in the Hermes-controlled benchmark workflow. V2 accepts only a frozen Gradle-wrapper command with `--rerun-tasks`; this prevents stale up-to-date reports from being mistaken for execution.
