# EP22 Federation owner reads

Federation composes public Identity, Render, Billing, Prompt, Extension and Entitlement queries. New projections expose only the read fields needed by these consumers. Owner implementations retain private persistence and policy dependencies. No business contract is added to shared-kernel; canonical actor remains Identity-resolved.

Identity Tenant/User projections enforce current authenticated tenant scope. ProjectReadQuery and WorkspaceQueries retain resource authorization. Render projections delegate to the existing authorized owner job queries, and export presets remain Render policy. Billing requires an explicit canonical actor plus matching ambient tenant before reading scoped durable usage, preserving metered ordering and quantity. Its existing bounded FREE/USD/zero overview remains a presentation default, not an assertion of a real balance; reading it no longer creates a BillingDecision.

Prompt definitions remain the existing global reusable catalog, not invented tenant-owned objects. Execution views filter tenant and user (or tenant ADMIN) before projecting fields and before Federation applies its existing limit of 20. Extension views omit internal rule/entity details and filter applicable tenant/user rules. Entitlement continues publishing its existing decision contract; loaders now pass authenticated actor/tenant rather than null scope.

Mapped loaders remain stateless, with no reusable cache or production DataLoader registration introduced. Owner calls execute on the dispatch thread and return completed/failed stages; they never hop to the unscoped common pool. Callers must dispatch in the authenticated request context. Dispatch without that scope fails closed. Missing allowed Identity rows map to absent keys; denied/dependency failures fail the batch without fabricating an ID, empty success or partial successful completion. Request-local DataLoader caches must not be shared across requests. No new asynchronous worker/context propagation mechanism is introduced.

GraphQL context uses verified server identity, explicitly binds resolver context, and treats Workspace headers only as selectors requiring Identity authorization. HTTP authentication covers `/graphql` whenever enabled. Production GraphQL remains disabled by existing configuration and lacks a base Query schema; the HTTP regression enables it only in a disposable test profile with a test-only root. This migration does not enable or deploy GraphQL, add fields, or establish real provider execution. Existing static dashboard placeholders are unchanged and are not authoritative financial/provider health facts.

The existing dashboard estimate arithmetic is now under Billing, with explicitly non-ledger semantics; Federation only formats the returned values. Entitlement loaders also carry the selected Workspace after Identity authorization, never directly trust the header.
